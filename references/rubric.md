# 评分细则（Rubric）

> 扣分制，不是印象分。每条分数都要能指回一个具体的缺陷。

## 计分规则

1. 从满分起扣：每个维度满分 = 权重，按命中的缺陷扣分。
2. 严重度单价：**重度 −6 · 中度 −3 · 轻度 −1**。
3. 单维度地板为 0，扣穿不补到别的维度。
4. **同句同类去重**：同一个句子里同一类型的缺陷只计一次（取最重的那次）。
5. **单句总量上限**：一句最多扣 9 分（= 1 重度 + 1 中度），防止一句话拖垮全篇。
6. 全文同一缺陷反复出现（≥3 次）：按"整篇性问题"计一次重度 + 其余按中度，不按次数累加。
7. 不属于任何维度的感受（"我就是不喜欢"）不计分。说不出缺陷，就不扣分。

总分 = 八个维度得分之和。四舍五入到整数。

## 八个维度

### 1. 完整度（18）— 句子成型吗

抓的是句子结构：缺了不该缺的成分、该断的没断、该连的没连。

| 严重度 | 锚点 |
|---|---|
| 重度 −6 | 整句只有名词短语或动词短语，读者不知道谁做了什么；连动/兼语结构断裂，一句话有两个谓语打架；长句嵌套三层以上导致主干消失 |
| 中度 −3 | 省略的主语要跨段才能找回；关联词只出现一半（"虽然…"没有"但是"）；"的"字结构套太多层 |
| 轻度 −1 | 单句超过 60 字，虽然能读但需要回看一遍 |

**不扣分**：承前省略主语且上文紧邻（"我们查了日志，没发现问题。"）；要点式列表里的短句；标题、口号。

### 2. 明白度（18）— 一次能读懂吗

抓的是"读者要付出多少解码成本"。这是本 skill 的主战场。

| 严重度 | 锚点 |
|---|---|
| 重度 −6 | 术语堆叠三层以上且无解释；内部速记（T1、上一步那个、老方案）无法解码；关键缩写首次出现未展开且非通用 |
| 中度 −3 | 复合名词串两层未拆（"用户增长策略迭代方案"）；同一个意思换三个说法反而更模糊；缺少必要的过渡导致跳步 |
| 轻度 −1 | 用词需要猜；代词离指代对象太远 |

**不扣分**：行业通用缩写（API、PDF、HTTP）；已在括号内解释过的自造词；目标读者明确是该领域专家时的专业术语。

### 3. 精确度（12）— 指代和限定唯一吗

| 严重度 | 锚点 |
|---|---|
| 重度 −6 | 指代对象有两个以上候选，读者只能猜；限定词丢失导致范围、概率、责任主体变化 |
| 中度 −3 | "这个""该方案"跨段指代；数量、时间、单位表述含糊（"近期""大幅""若干"） |
| 轻度 −1 | 同一句里两个"它"指不同东西 |

**不扣分**：上下文中唯一的指代（紧邻上一句的主语）；口语场景的模糊限定（"大概下周"）。

### 4. 简洁度（12）— 有没有多余的字

| 严重度 | 锚点 |
|---|---|
| 重度 −6 | 整段同义反复，同一个意思说了两遍；大段铺垫没有信息量 |
| 中度 −3 | 同义叠加（"非常关键且重要""基本上可以说是"）；凑字过渡（"值得一提的是""众所周知"） |
| 轻度 −1 | 相邻两句重复同一个动词或名词；"的的不休"（一句话四个"的"） |

**判据**：删掉之后意思不变 → 该删。删掉之后语气变硬或信息丢失 → 保留。

### 5. 语感（14）— 像人写的吗

抓"机械化表达"。注意：**规范不等于人话**。

| 严重度 | 锚点 |
|---|---|
| 重度 −6 | 通篇套壳（首先/其次/最后、综上所述），换成任何主题都成立；三段式排比纯凑结构无信息增量 |
| 中度 −3 | 每段用同一种句式开头；破折号 + 冒号解释结构连用（"X——也就是Y：Z"）；连接词密度过高（每两句一个"因此/此外/同时"） |
| 轻度 −1 | 连续三个句子长度几乎相同；结尾固定为"希望对你有帮助"式套话 |

**不扣分**：正式文档里必要的结构性连接词（长篇报告需要"综上所述"收口）；用户明确要求的模板化格式（周报、纪要）。

### 6. 得体度（10）— 对不对人、对不对场合

| 严重度 | 锚点 |
|---|---|
| 重度 −6 | 对客户/上级用命令式；承诺强度越界（把"尽量"写成"保证"）；情绪化判断混入事实陈述 |
| 中度 −3 | 称呼不统一（一会"您"一会"你"）；过度自谦或过度自信 |
| 轻度 −1 | 敬语堆砌；口语词混入正式文档 |

**不扣分**：用户明确要求的强硬语气；内部沟通的直白表达。

### 7. 格式（10）— 标点格式规范吗

| 严重度 | 锚点 |
|---|---|
| 重度 −6 | 标点缺失导致断句错误、语义变化；半角标点混入中文正文 |
| 中度 −3 | 中英文之间无空格（"使用Python脚本"）；数字单位不统一（"3天"与"72小时"混用）；括号套括号 |
| 轻度 −1 | 破折号、省略号滥用；列表符号混用（·、-、1. 交替）；行末多余空格 |

**不扣分**：Markdown 语法要求的符号；代码块内的一切。

### 8. 一致性（6）— 前后叫法统一吗

| 严重度 | 锚点 |
|---|---|
| 中度 −3 | 同一概念三种叫法（客户端/前端/用户端）；人称在段落间跳变 |
| 轻度 −1 | 数字格式不统一（"三"与"3"混用）；繁简混排 |

**不扣分**：为了区分两个不同事物而刻意换词。

## 等级与门禁

| 等级 | 分数 | 含义 |
|---|---|---|
| A | 95–100 | 可以直接发 |
| B | 90–94 | 达标，个别小瑕疵可接受 |
| C | 75–89 | 能读，但读者要干活 |
| D | <75 | 建议重写而不是改 |

**放行条件**：总分 ≥90 且 重度缺陷 = 0 且 三条红线全过。

分数 ≥90 但有重度缺陷 → 不放行。这是故意的：读者不会因为整体流畅就原谅那句看不懂的话。

## 打分自检（打完分问自己三句）

1. 我扣的每一分，能不能指到原文的某一句话？
2. 有没有把"我不喜欢这个风格"算成了缺陷？
3. 有没有因为"这段是我改的"而放水？

第 3 条最要命。所以评分和改写要分开做，见 SKILL.md「独立评审」。
