# 回炉协议（Rewrite Protocol）

> 改得越少，越不容易改坏。回炉的目标是修掉缺陷，不是重写一篇。

---

## 一、改写幅度：三档递进

默认从最小档开始，只有上一档不够时才升级。

| 档 | 动作 | 什么时候用 |
|---|---|---|
| **L1 修句内** | 补主语、换词、删冗余、改标点、拆开过长的定语 | 缺陷是局部的，句子骨架还在 |
| **L2 调结构** | 拆句、合句、换语序、补过渡、合并重复段 | 句子读完能懂，但要回头再看一遍 |
| **L3 重写段** | 整段重新组织，只保留事实与立场 | 缺陷密度 >40%，或整段逻辑坍塌（D12 重度 ≥2） |

**硬约束**：L3 只用于整段重写，不允许"顺手把全文都重写一遍"。全篇重写会把已经合格的句子改坏，而且几乎必然引入新的机械化表达。

---

## 二、改写顺序：删 → 补 → 顺 → 校

顺序不能换。

1. **删**（D5 冗余、D6 套话）：先砍掉不承载信息的字句。留着废话去补主语，等于给垃圾配包装。
2. **补**（D3 主谓、D2 速记、D1 省略）：把省掉的成分补回来，把速记翻译成人话。
3. **顺**（D7 指代、D12 跳步、D4 堆叠）：调语序、拆定语、补因果。
4. **校**（D9 格式、D10 术语、D11 语气）：最后统一标点、空格、称呼、术语。

先删后补的道理很简单：删完再看，很多"缺主谓"的句子已经整个不需要了。

---

## 三、保真检查（每轮都要做）

改完之后，逐条对回原文。六项全过才算改写有效：

| 检查 | 方法 |
|---|---|
| 事实没变 | 数字、日期、人名、产品名、链接，逐个对 |
| 范围没变 | "所有/部分/仅"、"会/可能/预计"，逐个对 |
| 责任没变 | "我/我们/团队/对方"，承诺主体不能换 |
| 结论没变 | 原来不建议的，改完还是不建议 |
| 术语没删 | 术语、专有名词原样保留；不得改成"建议执行"式官腔 |
| 语域与情态没变 | 原文口语就保持口语，书面就保持书面，一句话里不许混搭；"明确"不能改成"拍板"，"建议"不能改成"得先" |

**任何一项变了，这一轮改写作废**，回滚到上一版。不要试图"改回去一点点"——保真问题没有中间态。

---

## 四、退化与回滚

改写不一定变好。设一个明确的门槛：

```
新分 < 旧分 − 3   →  退化，回滚
|新分 − 旧分| ≤ 3 →  持平，保留新版（自然度更高时优先保留新版）
新分 > 旧分 + 3   →  进步，接受
```

**退化时不要放弃，先减小步长**：

1. 回滚到上一版。
2. 只修最严重的 3 条缺陷，其余不动（相当于把 L2/L3 降到 L1）。
3. 再评一次。仍然退化 → 停止回炉，交付上一版，并在报告里写清"再改会损失保真或自然度"。

这条规则的存在是因为：**过度润色本身就是一种机械化**。有些文本改到 88 分就到底了，硬推到 90 分只会让它变成四平八稳的官样文章。

---

## 五、循环结构

```
轮次 = 0
基线 = 原文

循环：
  轮次 += 1
  A. 冷读审稿（读原文，不看上一轮清单）→ 缺陷清单 + 八维得分 + 总分
  B. 判定：
       总分 ≥90 且 重度 = 0 且 红线全过
         → 交付，结束
  C. 改写：按「删→补→顺→校」，幅度 L1/L2/L3
  D. 保真检查：不过 → 回滚，步长减半，重来一次；再不过 → 终止
  E. 退化判定：退化 → 回滚 + 只修最严重 3 条
  F. 把本轮清单封存，进入下一轮
```

### 封存清单（关键）

进入下一轮审稿时，**先不看上一轮的缺陷清单**，重新通读原文。

照着清单打钩，永远能打出 90 分——因为你在验证"我改的地方改好了没有"，而不是"这段文字现在读起来怎么样"。前者是自我确认，后者才是审查。

### 终止条件

| 条件 | 动作 |
|---|---|
| 达标 | 交付终稿 |
| 达到轮次上限 | 交付最高分版本 + 未解决清单 |
| 连续两轮无进步（|Δ| ≤ 3） | 停止，交付最高分版本 |
| 保真无法保证 | 立即停止，交付原文 + 说明 |

**默认上限 4 轮**（含首审）。用户明确说"继续回炉"可追加 2 轮，但要在报告里注明"已进入收益递减区"。

轮次上限不是为了省事，是因为超过 4 轮之后，改动几乎都在"风格偏好"层面，继续改只是在迎合某个人的口味，不是在修病。

## 六、逐条改写示范

原文（模型生成，典型的六病叠加）：

> 首先，关于这个需求，我们需要明确一下目标。其次，基于当前的多模态能力，我们可以做一个端到端的一体化解决方案。最后，建议后续同步下进度。总的来说，这个方向非常关键且重要。

审稿：

| 位置 | 原句 | 缺陷 | 严重度 |
|---|---|---|---|
| 1 | 首先，关于这个需求，我们需要明确一下目标。 | D6 套壳 + D1 过度缩写（"明确一下"） | 中度 |
| 2 | 基于当前的多模态能力，我们可以做一个端到端的一体化解决方案。 | D4 术语堆叠 | 重度 |
| 3 | 建议后续同步下进度。 | D3 缺主谓 + D1 | 重度 |
| 4 | 总的来说，这个方向非常关键且重要。 | D5 同义叠加 + D6 套话 | 重度 |

得分：明白度 18 − 6 = 12；完整度 18 − 6 − 3 = 9；简洁度 12 − 6 = 6；语感 14 − 3 − 3 = 8；其余满分 → 总分 81，C。回炉。

改写（L2）：

> 这个需求先把目标定清楚。现在多模态模型能直接处理图片和文本，我们可以把原本要人工串起来的几个步骤合成一条链路，输入图片直接出结果。进度这块，建议每周同步一次。这个方向值得做。

复查：术语堆叠拆成了"用什么—做什么"（D4 修复）；"建议后续同步"补了主语和时间（D3、D1 修复）；"非常关键且重要"删成"值得做"（D5、D6 修复）。字数 74 → 88，信息量增加，没有新增事实。

---

## 七、改写的三条禁令

1. **不新增**：不添加原文没有的事实、数字、例子、承诺。想举例说明？用原文自带的。
2. **不代立场**：原文说"建议"，不能改成"决定"；原文犹豫，改完还得犹豫。
3. **不消毒**：不把有个性的表达磨平。原文的锋利、口语、自嘲，只要不违反红线，保留。

第 3 条最容易被忽略。审到最后，文字往往变得正确而平庸——那也是一种失败。
